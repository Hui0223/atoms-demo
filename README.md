# Atoms Demo · 一句话生成可运行的网页应用

> 在线体验：**https://atoms-demo-writing-test.ctq2013.workers.dev**（不用登录，可以直接点「游客体验」）

输入一句需求，多个智能体协作生成一个**能打开、能点、能存数据**的单文件网页应用。生成结果在沙箱里实时预览，可以继续用对话做增量修改、回滚版本、下载或分享，也能发布到作品广场。

```
① 一句话需求 → ② Planner 拆解 → Engineer×N 赛马编码 → QA 校验打分择优
            → ③ iframe 沙箱实时预览 → ④ 项目 / 版本 / 对话 / 任务状态全部落库
```

## 功能一览

| 模块 | 说明 |
| --- | --- |
| 注册 / 登录 / 游客 | 用户名密码注册。新密码是 PBKDF2-SHA256、10 万次（Workers 上限），存成 `pbkdf2_sha256$100000$<hex>`；旧的 2 万次纯 hex 仍能校验，登录成功后自动换成新参数。同一用户名 15 分钟内失败满 5 次，或同一 IP 满 20 次，返回 429「登录失败次数过多，请 15 分钟后再试」（窗口内正确密码也不放行）；成功登录只清用户名计数。不存在的用户名也会做一次同等成本的 PBKDF2。也可以一键游客体验；游客之后能**升级为正式账号，项目不丢** |
| 多智能体流水线 | 📋 Planner 把需求拆成结构化规格 → 💻 Engineer 编码 → 🧪 QA 做静态校验并评分；过程（阶段条、每路状态 / 字符速度 / 代码尾、重试日志、计时）全程可见 |
| **赛马模式（亮点）** | 1–3 路工程师并行（不同设计取向和温度；模型可选 DeepSeek / GLM / 混合，混合时各路交替用两个模型），错峰启动防 429。静态 9 项 + 运行时检查后自动择优，悬停能看到细项；落选方案保留为「候选」，可以一键采用。首个方案合格后，其余赛道有 50s 宽限，超时就提前收敛，避免拖慢整体 |
| 对话式**增量**迭代 | 模型只输出 SEARCH/REPLACE 补丁，在本地应用，不会全量重吐。已有版本时，新消息会先判断是「改当前应用」还是「做一个全新应用」：规则明确判为新应用就自动新建项目；模型判为新应用时先弹出选择（推荐新建）；判为修改则直接打补丁。补丁必须全部命中，QA 也要通过才落库（原子性），失败时保留上一版。用所选模型出补丁，补丁不合格再自动换另一个模型重试。每个任务限时 120s，可随时取消，前端显示 `Xs / 120s` |
| **新需求识别** | 规则看「做一个 / 再做一个 / 新建… + 应用 / 游戏 / 工具…」以及和当前标题、需求、规划的二元组是否重叠。`POST /api/projects/:id/intent` 带回 `source`：`rules` 或 `model`。规则给出 `new` 且置信度 ≥ 0.75 时直接新建项目，并沿用赛马路数、模型、演示模式、故障演练自动开跑。规则判为 unsure 且配置了模型时，再发一次短分类（失败仍是 unsure、`source` 仍为 `rules`）。模型判成 `edit` 直接走增量；模型判成 `new` 弹出选择，主按钮是「新建项目（推荐）」。规则仍然 unsure 时也弹出选择，不标推荐。Esc 或关闭等于取消、什么都不发。「让 AI 修复」永远走增量。真正打到模型的意图判断和生成任务共用每用户每小时 30 次；额度用尽时这次不再调模型，保持规则结果（unsure 就弹出选择），不报错。只走规则的调用另有每小时 120 次上限，超出返回 429 |
| **实时进度** | 阶段条：需求拆解 → 并行生成 (N 路) → 静态评分 → 运行时检查 → 完成（修改则是：生成补丁 → 应用补丁/QA → 运行时检查 → 完成），当前阶段带已用秒数。规划模型也推字符。每路显示排队 / 思考中 / 编写代码 / 已完成 / 失败 / 已中止、模型名、字符数、字/秒、耗时、按约 9000 字符估算并在完成前封顶 95% 的进度条，以及可折叠的最后约 400 字代码尾（输出节流）。代码尾只在该路处于思考或编写时默认展开；变成完成 / 失败 / 已中止后自动收起，除非用户自己点过。代码尾大约 6 行高，超出滚动。进度卡片本身更紧。用户没有往上翻聊天记录时，阶段切换会把进度卡片滚进视野。进度快照大约每 2 秒写入任务，刷新后轮询 `GET /api/jobs/:id` 仍能看到阶段和字符数。赛马表的数字和状态不换行，模型名去掉供应商标记和 `-flash`（悬停看全名），窄列里表格横向滚动；尚未做运行时检查的格子显示为淡色「…」 |
| **运行时检查** | 生成或修改落库后，浏览器把胜出方案和候选放进隐藏的 `sandbox="allow-scripts"` iframe（无同源、不桥接本站存储），收集 `window.onerror` / `unhandledrejection` / `console.error`，约 2.5 秒后判断白屏（可见文字 < 10 且可见元素 < 3）。回传后总分仍是 100 分制：分项「运行时检查」满分 15（白屏 0，否则每个不同错误扣 8）；有错误的方案总分再扣 30，白屏扣 40。若当前胜出者报错或白屏，而同任务的干净候选扣分后更高，自动改用该候选（换用写在同一条结果消息里）。全部报错则保留胜出者，并沿用预览里的「让 AI 修复」（不会自动连修）。任务完成时生成一次性凭证，只随 SSE `done` 和所有者的 `pendingRuntime` 下发；`POST /runtime-check` 校验所有者、任务属于该项目且状态为 done、凭证一致（用过即废，再次提交 409）。报告最多 8 条，版本必须属于该任务，错误条数和字段长度有上限，不合规则 400，最终分夹到 0–100。探针只接受来自该 iframe 的消息。结果改写原来那条 QA / 编辑消息（补上运行时列），不再另起一条；升级前已经写成两条的旧项目保持原样 |
| 运行时自愈 | 隐藏沙箱先做运行时检查并可能自动换方案；预览里若仍报错，可点「让 AI 修复」走增量修复（修完再查一次，不自动循环） |
| 版本管理 | 每次生成、修改、采用、回滚都会产生新版本，历史不覆盖；任何版本都能预览或回滚 |
| 预览沙箱 | `sandbox` iframe，不给同源权限，生成的代码拿不到本站登录态；注入的 Storage 桥让沙箱内的 `localStorage` 照常可用，并按项目持久化，**刷新后应用内数据还在** |
| 分享 / 导出 / 广场 | `/s/:id` 只对已公开作品返回分享页（CSP sandbox 隔离，不设 `X-Frame-Options`）。未公开和不存在都是同一句「作品不存在或未公开」，链接里不放令牌。未公开时点「分享」会先问「分享前需要先公开作品，是否公开并复制链接？」，确定后才公开并复制，取消则不动；取消公开后旧链接同样 404。预置示例保持公开。下载独立 HTML；公开后进入广场，他人可 Fork |
| 永不白屏（四层防线） | 节流（错峰）→ 重试 → 备用模型通道 → **内置模板降级**（5 套手写的完整可用模板，加上规则引擎做「换色、深色、改标题、字号、圆角」类修改）。赛马主通道最多 3 次，失败后等待 1s 再 2s（带 0–400ms 抖动）；4s 只会出现在存在第 4 次尝试时。可重试的 429/503 若带 `Retry-After`（秒数或 HTTP-date），等待取 `max(退避, Retry-After)`，封顶 8 秒，并且不能超过任务截止时间，放不下就换下一条通道。备用通道最多 2 次。两个备用 Secret 都配置时，备用通道用独立地址和密钥，缺一则仍用主通道那一套。给用户看的模型错误是中文类别（限流、5xx、鉴权、额度、超时、网络、截断），不带上游响应体；故障演练显示为「[故障演练] 模型繁忙（模拟 429）」这类句子。前端标注「AI 生成 / 备用模型 / 演示模式」 |
| 故障演练 | 生成选项里可以手动模拟「主模型 429」「全部模型不可用」「运行时报错（方案 A 注入错误）」。前两项只影响模型通道；运行时报错在静态评分之后往方案 A 的 HTML 里注入一段必抛错脚本，不改模型请求。也可以勾选「演示模式」完全不调用模型 |
| 任务状态落库 | 生成任务在 Durable Object 内执行并写库（不受 Worker 单请求 CPU 限制），刷新页面能自动恢复进度。对象启动时，仍是 `running` / `canceling` 的任务立刻标为失败（部署后旧实例有宽限期，实测约 30 秒后生效），对话里加一条系统消息：「任务中断：服务重启（如刚部署新版本），本次生成未完成，已有版本不受影响，可直接重新生成」。另保留 150 秒无心跳判定。SSE 在没有 `done` 时结束，或轮询看到失败/取消，前端用任务上的错误文案提示，并马上恢复输入框，方便直接再生成 |

## 技术栈

- **运行平台**：Cloudflare Workers（免费、自带 https、不需要备案），同一个 Worker 托管静态前端和 API
- **数据持久化**：Durable Object 内置 SQLite，强一致、随部署持久保存，不存在“免费实例重启丢库”的问题
- **大模型**：Anthropic Messages 兼容接口（`/v1/messages` 流式 SSE），白名单内两个模型，前端「🧠 模型」下拉选择：
  - `deepseek-v4-flash`（默认）
  - `glm-5.3-flash`（推理较慢，长需求通常 60–70s）
  - 「混合」：赛马各路交替使用两个模型，由 QA 评分择优
  - Planner / Engineer / Editor 都用所选模型；调用失败自动切到另一个模型，两者都不可用再降级到模板
  - 模型名放在 `wrangler.toml` 的 `[vars]`（`MODEL_DEEPSEEK` / `MODEL_GLM`）；后端只接受这两个，其他取值一律回落到默认
  - 接口地址和密钥只通过 `wrangler secret put ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 注入，**仓库和代码里没有任何 Key**
  - 可选：备用通道单独走另一套接口时，两个都要配：`wrangler secret put ANTHROPIC_BACKUP_BASE_URL` 和 `wrangler secret put ANTHROPIC_BACKUP_AUTH_TOKEN`。只配其中一个时，备用通道仍用主通道的地址和密钥
- **前端**：原生 ES Module + CSS，不需要构建；后端是原生 JS，测试用 Node 内置 `node:test`

## 本地运行

需要 Node.js ≥ 22，以及一个 Cloudflare 账号（免费版即可）。

```bash
npm install
npm test                 # 单元测试
npx wrangler login       # 首次使用时登录 Cloudflare
npm run dev              # 本地开发：http://localhost:8787（模型接口配置写在 .dev.vars，已被 .gitignore 排除）
npx wrangler secret put ANTHROPIC_BASE_URL     # 首次部署前配置模型接口
npx wrangler secret put ANTHROPIC_AUTH_TOKEN
# 可选。两个都设置时，备用通道使用独立地址和密钥；只设置其中一个则仍走主通道
npx wrangler secret put ANTHROPIC_BACKUP_BASE_URL
npx wrangler secret put ANTHROPIC_BACKUP_AUTH_TOKEN
npm run deploy           # 部署到 <name>.<subdomain>.workers.dev
```

- 没有模型接口时（未配置 Secret、或 `wrangler.toml` 里设 `AI_DISABLED = "1"`），或者在页面勾选「演示模式」，整个流程照样能跑完并出预览。
- 本地开发如需真实模型，在 `.dev.vars` 里写 `ANTHROPIC_BASE_URL=...` 和 `ANTHROPIC_AUTH_TOKEN=...`（不要提交）。备用通道同理，可再写 `ANTHROPIC_BACKUP_BASE_URL` 与 `ANTHROPIC_BACKUP_AUTH_TOKEN`，两个都有才生效。
- 本轮的分享可见性、登录限流、安全响应头等改动在当前仓库里。按要求没有重新部署，页首的在线链接仍是上一版。

## 设计思路与关键取舍

1. **先保证“链接活着、闭环跑通、不会白屏”，再堆亮点。** 选 Workers + Durable Object(SQLite)，一次部署就同时解决 https 访问和持久化存储，没有冷启动、免费实例休眠、临时文件系统这类常见坑；模型密钥只放在 Worker Secret 里，不进仓库。
2. **产物是单文件 HTML。** 可以直接用 iframe 运行，也能下载后双击打开，最容易验证“真的能跑”。代价是不支持多文件或后端工程，这是有意的范围控制。
3. **只把赛马做深。** 赛马最能体现 Atoms 的特点：用并行和择优换质量与稳定性。评分规则可解释、可复现，没用 LLM 当评委，省额度也省时间；代价是对“视觉美观”只能间接衡量，所以加了设计系统注入来拉齐视觉下限。
4. **迭代走真增量。** 输出 token 少，不会撞上限、不会卡死；配合原子落库和版本快照，“改一次崩一次”的问题从机制上就规避了。
5. **安全隔离。** 生成的代码属于不可信内容，所以预览和分享页都放在无同源的沙箱里运行，持久化通过宿主桥接实现。主站静态资源由 Assets 直接返回（`run_worker_first` 只覆盖 `/api/*` 和 `/s/*`），安全响应头写在 `public/_headers`；`/api/*` 的 JSON 和 SSE 由 Worker 再加一遍 `nosniff`、`Referrer-Policy`、`X-Frame-Options: DENY`、`Permissions-Policy`。主站 CSP 含 `script-src 'unsafe-inline'` 和 `style-src 'unsafe-inline'`，因为 srcdoc 预览、隐藏探针和缩略图会继承父页面的 CSP，生成应用里的内联脚本和样式必须能执行。真正的隔离是 iframe `sandbox` 且不给 `allow-same-origin`。无头 Chrome 在这条 CSP 下（`frame-src` / `form-action` 不含 `about:`）确认：srcdoc 内联脚本能跑，模板那种 `preventDefault` 的表单、`alert` / `confirm`、`blob:` 下载和 `window.open`（sandbox 含 `allow-popups`）都没有触发 `securitypolicyviolation`。分享页继续只用 CSP `sandbox`，不加 `X-Frame-Options`，避免和沙箱页冲突。入口 `catch` 只返回「服务器开小差了，请稍后重试（编号 …）」，原始异常留在服务端日志。

## 排障记录

| # | 遇到的坑 | 定位过程 | 解决方式 | 验证结果 |
| --- | --- | --- | --- | --- |
| 1 | 笔试飞书文档用 curl 拿不到内容 | 返回的是 passport 登录页 HTML（含 `window.passportSettings`） | 改用无头 Chrome 渲染，逐块滚动采集正文 | 拿到完整题目，并与官方避坑指南交叉核对 |
| 2 | `wrangler deploy` 报 “requires Node.js ≥ 22” | 本机 Node 是 v20 | 下载 Node 22 便携版来跑 wrangler，`package.json` 里声明 `engines` | 部署成功 |
| 3 | 刚部署完访问返回 `error code: 1101` | 用 `wrangler tail` 看实时日志，后续请求恢复正常，判断是部署传播期间的瞬时异常 | 加上 `observability` 日志；之后部署完都等几秒再验证 | 后续访问全部正常 |
| 4 | 调试用的 API Token 没有 D1/KV 权限（`Authentication error`） | 逐个调接口确认只有 Workers Scripts 权限 | 改用 **Durable Object 内置 SQLite** 做持久化，它随脚本迁移创建，不需要额外权限 | 刷新、重部署后数据都在 |
| 5 | 赛马时 B 路模型连续出现「输出停滞」，整个任务拖满 120s | SSE 日志显示 A 路 57s 完成，B 路两次 35s 无数据 | ① 加入“首个合格方案出现后宽限 N 秒就提前收敛”；② 每条赛道都有可 race 的中止器（取消或收敛时立刻生效，不用等读超时） | 2 路赛马总耗时从 120s 降到 60–75s |
| 6 | 增量修改耗时 85s，不符合“轻量修改 1 分钟内返回” | 推理型模型补丁小但首包慢 | 补丁走精简提示与小 max_tokens；补丁未全部命中就自动换另一个模型（原子性：部分命中也不落库） | 小改动约 8s，加功能类 40–65s |

## 已知限制

- 两个模型都默认开启思考（thinking），接口侧无法关闭；GLM-5.3 Flash 思考更久，长需求单路约 60–70s，偶尔仍会因停滞切到备用模型。
- 运行时检查只覆盖首屏加载后约 2.5 秒（不点击、不跑长定时器）。检查通过后，预览里才出现的错误仍靠「让 AI 修复」。
- 生成的应用限定为单文件前端，不支持多文件工程、npm 依赖或后端代码。
- 分享页处于强隔离沙箱，应用内数据只保存在内存里（站内预览和下载的独立 HTML 都能持久化）。
- 主站 CSP 允许内联脚本，是为了让 srcdoc 里的生成应用能跑；不要把它理解成生成代码和本站同源。预览 iframe 没有 `allow-same-origin`。
- 登录锁定按 `cf-connecting-ip` 计数。没有这个头时只限制用户名，不会把所有未知 IP 合成一桶。
