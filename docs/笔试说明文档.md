## 一、实现思路与关键取舍

**最小闭环**：一句话需求 → 多智能体生成单文件 HTML 应用 → sandbox iframe 实时预览 → 项目、版本、对话和任务状态全部持久化。

| 决策 | 选择 | 原因 / 取舍 |
| --- | --- | --- |
| 部署平台 | Cloudflare Workers（静态资源和 API 同一个 Worker） | 免费，自带 https，不用备案，没有冷启动和休眠；不需要维护服务器 |
| 持久化 | Durable Object 内置 SQLite | 免费实例的文件系统是临时的，这是常见扣分点；DO SQLite 强一致、随部署长期保存，还能直接写 SQL |
| 模型 | Anthropic 兼容接口，白名单两个模型：DeepSeek V4 Flash（默认）、GLM-5.3 Flash；前端下拉可选，也可选「混合」让赛马各路交替使用 | 两个模型互为备用：所选模型失败自动切到另一个，再失败降级到模板。接口地址和密钥只存在 Worker Secret 里，代码和仓库**零 Key**；后端只接受白名单模型 |
| 产物形态 | 单文件 HTML（内联 CSS/JS，localStorage 持久化） | 能 iframe 运行，也能下载双击打开，“真能跑”最好验证；放弃多文件工程和后端，控制复杂度 |
| 亮点方向 | **只把赛马模式做深**，迭代 / 版本 / 分享作为配套 | 赛马最贴 Atoms 的招牌能力。静态评分用 9 项可解释规则（结构完整、交互、交互丰富度、持久化、移动端、脚本闭合、需求覆盖、视觉、完整度），生成后再加一项浏览器沙箱里的运行时检查。没用 LLM 当评委，省额度也省时间 |
| 视觉质量 | 生成后注入 atoms-ui 基础样式库，提示词要求模型使用其类名 | Flash 档模型的审美参差不齐。注入后视觉下限统一，模型输出也更短更快（产物截图对比后才定下这个方案） |
| 迭代方式 | **真增量**：SEARCH/REPLACE 补丁、原子落库、补丁不合格自动换另一个模型 | 避免全量重吐带来的截断和卡死；补丁没全部命中或 QA 不通过时都不落库，上一版保持不变 |
| 稳定性 | 四层防线：错峰节流 → 指数退避 → 备用模型 → 模板降级 | 赛马主通道最多 3 次，间隔 1s→2s，带 0–400ms 抖动（4s 只在还有第 4 次尝试时出现）。可重试的 429/503 读取 Retry-After，等待取较大值并封顶 8 秒，放不进截止时间就换通道。备用通道最多 2 次。上游 429 / 超时 / 额度耗尽都由我们自己兜底。生成任务异常不会穿透；入口兜底 500 只返回通用提示和编号，不暴露原始错误。给用户看的模型错误是中文类别，不带上游正文。前端标注 AI / 备用 / 演示模式 |
| 超时与取消 | 单任务预算 120s，另有首包 45s、停滞 35s 超时；用户可随时取消 | 等待时有阶段条、每路字符速度和实时代码尾。取消实测 1.5–2.5 秒生效（服务端每 2 秒查一次取消标记，流式读取大约每 1.5 秒再查一次）。进度快照随任务落库，刷新后轮询仍能看到阶段和字符数。对象重启后，原先要干等约 150 秒的运行中任务会在新实例启动时标失败（实测部署后约 30 秒），并在对话里说明可重新生成 |
| 安全 | 生成代码运行在无同源的 sandbox iframe 里；分享页用 CSP sandbox，主站用 `public/_headers` | 生成代码不能读取宿主登录态；Storage 桥接让沙箱里的 localStorage 按项目持久化。主站 CSP 允许 `'unsafe-inline'`，因为 srcdoc 会继承父页面策略，内联脚本和样式必须能跑；隔离靠 sandbox 且不给同源。未公开作品的分享链接返回和「不存在」相同的 404。运行时回传带一次性凭证 |
| 账号 | 用户名密码（PBKDF2-SHA256，新哈希 10 万次；旧的 2 万次仍能登录并在成功后升级）+ 一键游客 + 游客升级 | 评审打开就能体验，不用先注册；需要长期保存时可以无损升级。15 分钟内同一用户名失败满 5 次或同一 IP 满 20 次会锁定 |

**多智能体分工**：📋 Emma（产品经理）把需求拆成结构化 JSON 规格 → 💻 Alex（工程师）×N 并行编码，分别是 A 稳健实用、B 视觉创意、C 极简（混合模式下各路交替用 DeepSeek / GLM）→ 🧪 Iris（测试与评审）做 QA 校验、打分、择优，落选方案保留为候选 → ✏️ Alex（迭代）出增量补丁。

## 二、当前完成程度

**已完成（线上可测）**
- 注册 / 登录 / 游客 / 游客升级；项目列表、重命名、删除
- 需求拆解 → 1–3 路赛马生成 → QA 评分择优 → 候选方案一键采用
- 流式进度：阶段条（需求拆解 → 并行生成 → 静态评分 → 运行时检查 → 完成；修改则是生成补丁 → 应用补丁/QA → 运行时检查 → 完成）、每路状态 / 字符 / 速度 / 进度条 / 可折叠代码尾、重试日志、`Xs / 120s`、取消。规划阶段也推字符。代码尾只在该路正在输出时默认展开，结束后自动收起（用户手动开关过的保持原样），高度大约 6 行。用户没往上翻时，阶段变化才把进度卡片滚进视野。进度快照约每 2 秒写入任务，刷新后轮询仍能恢复。赛马表数字不换行，模型名缩短后悬停看全名，窄列横向滚动
- 新需求识别：已有版本后再发消息，会判断是改当前应用还是做全新应用。接口返回 `source`（`rules` / `model`）。规则判为新应用且置信度 ≥ 0.75 就自动新建项目并接着生成。模型判为修改则直接增量；模型判为新应用时弹出选择，主按钮是「新建项目（推荐）」。规则仍然拿不准时也弹出选择，不标推荐（Esc 取消）。「让 AI 修复」始终是增量修改。真正调用模型的意图判断计入每小时 30 次（和生成共用）；额度用尽时不调模型，保持规则结果。只走规则时每小时最多 120 次

- 增量修改（补丁）、原子落库、补丁失败自动换模型、超时与取消
- 版本历史、任意版本预览、回滚（以新版本形式，历史不丢）

**未做 / 已知限制**
- 赛马评分是规则打分，对“美观程度”只能间接衡量，没有接入 LLM 评委或截图评审
- 产物只支持单文件前端，不支持多文件工程、npm 依赖、后端或数据库
- 两个模型都强制开启思考，接口侧关不掉；GLM 更慢，偶尔会因输出停滞切到备用模型
- 运行时检查只看加载后约 2.5 秒的首屏，不点击、不覆盖之后才触发的错误；这类仍靠预览里的「让 AI 修复」
- 分享页处于强隔离沙箱，应用内数据只保存在内存
- 没有做团队协作、实时多人编辑
- 部署后正在跑的任务约 30s 后才显示「任务中断」（Cloudflare 旧实例的宽限期），不是立即
- CSP 保留 `'unsafe-inline'`：预览用 srcdoc iframe，会继承父页面 CSP；隔离依靠无同源 sandbox

## 三、如果继续投入时间（按优先级）

1. **P0 评审质量**：加入“截图 + 视觉模型评审”或 LLM 评委，与规则分加权，解决“分数高但不好看”的问题；同时给赛马结果做左右对比预览。
2. **P0 迭代体验**：补丁预览 diff（应用前确认）、按选区修改（在预览里点选元素，再描述要怎么改）、多轮修改的上下文压缩。
3. **P1 产物能力**：多文件工程（Vite 模板）+ 在线构建；可选的后端数据 API（每个生成应用一个 KV / DO 命名空间），让生成的应用跨设备同步数据。
4. **P1 成本与稳定性**：输出缓存（相同需求复用）、按用户的额度可视化、接入第二家模型平台作跨厂商备用通道。
5. **P2 社区**：广场的点赞 / 排序 / 标签、模板市场、一键“基于此作品再创作”的需求继承。

## 排障补充（相对 README 排障记录 15–27）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 新需求被当作修改，叠加多个应用 | 已有版本后，输入框把每条消息都设成 `edit` | 发送前用规则（拿不准再问一次短模型分类）。规则明确的新应用自动新建项目；模型判成新应用时先确认，推荐项是新建项目；模型判成修改则直接打补丁。服务端 `edit` 仍然只打补丁 |
| 生成 45–70 秒无反馈 | 规划阶段不推流，赛马开始前界面是静的 | 阶段条、规划字符、每路速度和代码尾实时更新；进度写入任务，刷新后轮询还能看到 |
| 静态评分高的方案运行时报错仍胜出 | 评分只有静态规则 | 隐藏沙箱回报错误 / 白屏后下调总分，并在有更干净的候选时自动换方案。故障演练可以故意让方案 A 抛错来看这次改判 |
| 私有作品分享链接可被访问 | 分享页不看是否公开 | 未公开和不存在都返回「作品不存在或未公开」。分享前先确认再公开；取消公开后旧链接 404。预置示例仍公开 |
| 部署后运行中任务卡住约 150 秒且无提示 | 重启后 `running` 行没有人接着跑，只能等到心跳超时 | 对象启动时立刻标失败，并写一条系统消息。150 秒判定保留。前端看到失败/取消就提示并恢复输入框 |
| 登录无失败限流，意图接口绕过额度 | 登录失败不计数；每小时 30 次只数生成任务 | 用户名 15 分钟 5 次、IP 20 次锁定。打到模型的意图判断并进 30 次，用尽则不调模型。规则意图每小时 120 次 |
| 手机端顶栏竖排 | 窄屏导航被挤成竖排文字 | `nowrap`、可横向滚动；窄屏隐藏 Demo、缩短「升级」、再窄则隐藏长用户名。360px 与 390px（游客登录 / 未登录）无头 Chrome 看过，链接保持一行 |
| 500 和上游原文泄露 | 异常消息和模型响应体直接返回页面 | 500 只给通用提示和编号。用户可见的模型错误走中文类别，故障演练是「[故障演练] 模型繁忙（模拟 429）」 |
| 未读 Retry-After | 重试间隔固定，不看响应头 | 429/503 的 Retry-After 参与等待，封顶 8 秒。主通道最多 3 次，间隔 1s→2s，0–400ms 抖动 |
| 赛马结果两条消息 | 运行时检查再插一条对话 | 改写原来那条 QA/编辑消息，换方案也写在同一条里 |
| 运行时检查报告可伪造 | 回传不校验来源 | 一次性凭证，用过即废；报告条数和字段有上限，分数夹到 0–100 |
| PBKDF2 迭代偏低 | 2 万次纯 hex | 新哈希 10 万次自描述格式；旧哈希仍能登录，成功后升级 |
| 主站无安全响应头 | 静态资源不经过 Worker | `public/_headers` 加 CSP 等；`/api` 由 Worker 加头。分享页不加 `X-Frame-Options`。`unsafe-inline` 是因为 srcdoc 继承 CSP，隔离靠无同源 sandbox |
