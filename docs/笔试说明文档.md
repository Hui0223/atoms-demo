## 一、实现思路与关键取舍

**最小闭环**：一句话需求 → 多智能体生成单文件 HTML 应用 → sandbox iframe 实时预览 → 项目、版本、对话和任务状态全部持久化。

| 决策 | 选择 | 原因 / 取舍 |
| --- | --- | --- |
| 部署平台 | Cloudflare Workers（静态资源和 API 同一个 Worker） | 免费，自带 https，不用备案，没有冷启动和休眠；不需要维护服务器 |
| 持久化 | Durable Object 内置 SQLite | 免费实例的文件系统是临时的，这是常见扣分点；DO SQLite 强一致、随部署长期保存，还能直接写 SQL |
| 模型 | Anthropic 兼容接口，白名单两个模型：DeepSeek V4 Flash（默认）、GLM-5.3 Flash；前端下拉可选，也可选「混合」让赛马各路交替使用 | 两个模型互为备用：所选模型失败自动切到另一个，再失败降级到模板。接口地址和密钥只存在 Worker Secret 里，代码和仓库**零 Key**；后端只接受白名单模型 |
| 产物形态 | 单文件 HTML（内联 CSS/JS，localStorage 持久化） | 能 iframe 运行，也能下载双击打开，“真能跑”最好验证；放弃多文件工程和后端，控制复杂度 |
| 亮点方向 | **只把赛马模式做深**，迭代 / 版本 / 分享作为配套 | 赛马最贴 Atoms 的招牌能力。静态评分用 9 项可解释规则（结构完整、交互、交互丰富度、持久化、移动端、脚本闭合、需求覆盖、视觉、完整度），生成后再加一项浏览器沙箱里的运行时检查。没用 LLM 当评委，省额度也省时间 |
| 视觉质量 | 生成后注入 atoms-ui 基础样式库，提示词要求模型使用其类名 | Flash 档模型的审美参差不齐。注入后视觉下限统一，模型输出也更短更快（产物截图对比后才定下这个方案） |
| 迭代方式 | **真增量**：SEARCH/REPLACE 补丁、原子落库、补丁不合格自动换另一个模型 | 避免全量重吐带来的截断和卡死；补丁没全部命中或 QA 不通过时都不落库，上一版保持不变 |
| 稳定性 | 四层防线：错峰节流 → 指数退避重试（1/2/4s + 抖动，封顶 3 次）→ 备用模型 → 模板降级 | 上游 429 / 超时 / 额度耗尽都由我们自己兜底。所有异常都在任务层捕获，不会穿透成 500；前端标注 AI / 备用 / 演示模式 |
| 超时与取消 | 单任务预算 120s，另有首包 45s、停滞 35s 超时；用户可随时取消 | 等待时有阶段条、每路字符速度和实时代码尾；取消约 1 秒内生效；进度快照随任务落库，刷新后轮询仍能看到阶段和字符数 |
| 安全 | 生成代码运行在无同源的 sandbox iframe 里，分享页加 CSP sandbox | 生成代码属于不可信内容，不能读取宿主登录态；用 Storage 桥接让沙箱里的 localStorage 可用并按项目持久化 |
| 账号 | 用户名密码（PBKDF2）+ 一键游客 + 游客升级 | 评审打开就能体验，不用先注册；需要长期保存时可以无损升级 |

**多智能体分工**：📋 Emma（产品经理）把需求拆成结构化 JSON 规格 → 💻 Alex（工程师）×N 并行编码，分别是 A 稳健实用、B 视觉创意、C 极简（混合模式下各路交替用 DeepSeek / GLM）→ 🧪 Iris（测试与评审）做 QA 校验、打分、择优，落选方案保留为候选 → ✏️ Alex（迭代）出增量补丁。

## 二、当前完成程度

**已完成（线上可测）**
- 注册 / 登录 / 游客 / 游客升级；项目列表、重命名、删除
- 需求拆解 → 1–3 路赛马生成 → QA 评分择优 → 候选方案一键采用
- 流式进度：阶段条（需求拆解 → 并行生成 → 静态评分 → 运行时检查 → 完成；修改则是生成补丁 → 应用补丁/QA → 运行时检查 → 完成）、每路状态 / 字符 / 速度 / 进度条 / 可折叠代码尾、重试日志、`Xs / 120s`、取消。规划阶段也推字符。代码尾只在该路正在输出时默认展开，结束后自动收起（用户手动开关过的保持原样），高度大约 6 行。用户没往上翻时，阶段变化才把进度卡片滚进视野。进度快照约每 2 秒写入任务，刷新后轮询仍能恢复。赛马表数字不换行，模型名缩短后悬停看全名，窄列横向滚动
- 新需求识别：已有版本后再发消息，会判断是改当前应用还是做全新应用。接口返回 `source`（`rules` / `model`）。规则判为新应用且置信度 ≥ 0.75 就自动新建项目并接着生成。模型判为修改则直接增量；模型判为新应用时弹出选择，主按钮是「新建项目（推荐）」。规则仍然拿不准时也弹出选择，不标推荐（Esc 取消）。「让 AI 修复」始终是增量修改
- 运行时检查：胜出方案和候选在隐藏沙箱 iframe（只允许脚本、无同源）里跑约 2.5 秒，统计脚本错误和白屏。有错误总分扣 30，白屏扣 40；干净且因此超过胜出者的候选会自动换上。同一任务只记一次。全部报错则保留原胜出者，并给出「让 AI 修复」
- 模型下拉选择（DeepSeek V4 Flash / GLM-5.3 Flash / 混合），每路卡片显示所用模型
- 增量修改（补丁）、原子落库、补丁失败自动换模型、超时与取消
- 版本历史、任意版本预览、回滚（以新版本形式，历史不丢）
- 预览：桌面 / 手机视图、代码查看与复制、运行时错误捕获 + 「让 AI 修复」
- 预览内数据持久化（刷新后仍在）、分享页、下载 HTML、公开到广场、Fork
- 作品广场预置 5 个官方示例（不依赖模型）
- 降级：5 套模板 + 规则引擎；演示模式；故障演练（主模型 429 / 全部不可用 / 运行时报错：方案 A 在静态评分后注入抛错脚本，模型请求不受影响）
- 任务状态落库、刷新后恢复、心跳超时自动判定中断；每用户每小时 30 次生成限流、游客创建限流
- 单元测试 15 项（含意图分类、运行时加减分、故障注入与探针脚本）；线上 E2E 截图 44 张（30–44 为本轮新增）

**线上实测数据**（2026-10-01）
- 2 路赛马（DeepSeek / 混合）：45–115s，多数 50–85s
- GLM-5.3 Flash 单路生成（房贷计算器）：70s，87 分
- 轻量修改（如修正弹窗默认显示）：约 8s；新增功能 / 换色 + 新增统计：40–65s（两个模型都测过）
- 取消：约 1s 生效
- 故障演练：DeepSeek 模拟 429 → 自动切到 GLM，88s 出结果；全部模型不可用时约 7s 降级出模板应用

**本轮新增功能实测**（2026-10-01 23:30–23:55，Chrome headless 驱动，两个域名都测过）
- 新需求识别：番茄钟项目里输入「做一个记账本应用，可以记录收入支出并按月统计」→ 规则判定，约 2.5s 内自动新建项目并开始生成，原项目版本数不变（截图 36、37）；「我想要一个待办清单」规则拿不准 → 模型判别约 4s → 弹出「新建项目（推荐）/ 修改当前应用」，取消后什么都不发（截图 41）
- 增量修改不受影响：「把主色改成绿色」仍走 SEARCH/REPLACE 补丁，14–18s 完成，同项目新增 1 个版本（截图 34、35）
- 实时进度：规划阶段约 5s 内开始出字符；每路字符数 / 字速（DeepSeek 约 430 字/秒）/ 耗时 / 代码尾实时刷新（截图 30、31、39、44）
- 2 路赛马（DeepSeek）总耗时 69–115s（含约 3s 运行时检查）；GLM 单路 72s（含运行时检查）
- 运行时检查：故障演练「运行时报错」下，方案 A 静态 96 分 → 运行时 1 个错误 → 最终 66 分，自动改用方案 B（92 分），分享页输出的也是方案 B（截图 32、33）；静态同分时 A 从 90 降到 60，B 直接胜出
- 取消：约 1.5s 生效，已有版本不变（截图 38）
- 全部模型不可用：约 15s 降级出「任务看板」模板，模板也通过运行时检查（截图 42、43）

**未做 / 已知限制**
- 赛马评分是规则打分，对“美观程度”只能间接衡量，没有接入 LLM 评委或截图评审
- 产物只支持单文件前端，不支持多文件工程、npm 依赖、后端或数据库
- 两个模型都强制开启思考，接口侧关不掉；GLM 更慢，偶尔会因输出停滞切到备用模型
- 运行时检查只看加载后约 2.5 秒的首屏，不点击、不覆盖之后才触发的错误；这类仍靠预览里的「让 AI 修复」
- 分享页处于强隔离沙箱，应用内数据只保存在内存
- 没有做团队协作、实时多人编辑

## 三、如果继续投入时间（按优先级）

1. **P0 评审质量**：加入“截图 + 视觉模型评审”或 LLM 评委，与规则分加权，解决“分数高但不好看”的问题；同时给赛马结果做左右对比预览。
2. **P0 迭代体验**：补丁预览 diff（应用前确认）、按选区修改（在预览里点选元素，再描述要怎么改）、多轮修改的上下文压缩。
3. **P1 产物能力**：多文件工程（Vite 模板）+ 在线构建；可选的后端数据 API（每个生成应用一个 KV / DO 命名空间），让生成的应用跨设备同步数据。
4. **P1 成本与稳定性**：输出缓存（相同需求复用）、按用户的额度可视化、接入第二家模型平台作跨厂商备用通道。
5. **P2 社区**：广场的点赞 / 排序 / 标签、模板市场、一键“基于此作品再创作”的需求继承。

## 排障补充（相对 README 排障记录 15–17）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 新需求被当作修改，叠加多个应用 | 已有版本后，输入框把每条消息都设成 `edit` | 发送前用规则（拿不准再问一次短模型分类）。规则明确的新应用自动新建项目；模型判成新应用时先确认，推荐项是新建项目；模型判成修改则直接打补丁。服务端 `edit` 仍然只打补丁 |
| 生成 45–70 秒无反馈 | 规划阶段不推流，赛马开始前界面是静的 | 阶段条、规划字符、每路速度和代码尾实时更新；进度写入任务，刷新后轮询还能看到 |
| 静态评分高的方案运行时报错仍胜出 | 评分只有静态规则 | 隐藏沙箱回报错误 / 白屏后下调总分，并在有更干净的候选时自动换方案。故障演练可以故意让方案 A 抛错来看这次改判 |
